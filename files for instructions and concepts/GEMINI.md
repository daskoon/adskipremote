# GEMINI Project Analysis: AdSkipRemote

This document provides a comprehensive overview of the `AdSkipRemote` project, its architecture, and development conventions, generated by Gemini.

## 1. Project Overview

`AdSkipRemote` is a multi-module Android application designed to allow a user to skip YouTube advertisements playing on their phone by using their Wear OS watch as a remote control.

The project consists of two main components:
1.  **Phone App (`app` module):** An Android application that runs an `AccessibilityService`. This service listens for commands from the watch and, upon receiving one, programmatically finds and "clicks" the "Skip Ad" button within the official YouTube application.
2.  **Watch App (`wear` module):** A Wear OS application that provides the user interface to send the skip command. It includes a main activity with a button and a Wear OS Tile for quick access from the watch face carousel.

### Key Technologies & Architecture

*   **Language:** 100% **Kotlin**.
*   **Platform:** Android (minSdk 26) and Wear OS (minSdk 30).
*   **Build System:** **Gradle** with a multi-module structure (`:app`, `:wear`).
*   **Dependency Management:** The project uses a **Gradle Version Catalog** (`gradle/libs.versions.toml`) for centralized and clean dependency management.
*   **Communication:** The watch and phone communicate using the **Wearable MessageClient API** from the Google Play Services library. The communication is two-way: the watch sends a "skip" command, and the phone sends back a "success" or "failure" confirmation.
*   **Core Logic:** The phone app's primary functionality is handled by an **`AccessibilityService`**, which is the standard Android API for inspecting and interacting with the UI of other applications. Ad detection is performed by searching for the button's `View ID`, with a fallback to text search for robustness.
*   **UI:**
    *   The watch app's UI is built declaratively using **Jetpack Compose for Wear OS**.
    *   The phone app's UI uses the traditional Android XML layout system.

## 2. Building and Running

This project is configured to be built using standard Android toolchains.

### Recommended Method: Android Studio

1.  Ensure you have a recent version of **Android Studio** installed.
2.  Open the project by selecting the root `AdSkipRemote` directory via **File > Open**.
3.  Allow Android Studio to sync the project with the Gradle files. It will download all necessary dependencies.
4.  Connect a physical phone and watch with developer options and debugging enabled.
5.  Select the **`app`** run configuration from the toolbar, choose your phone as the target device, and click the **Run (▶)** button.
6.  Select the **`wear`** run configuration, choose your watch as the target device, and click **Run (▶)**.
7.  After installation, open the app on the phone and follow the on-screen instructions to **enable the Accessibility Service**.

### Advanced Method: Command Line (CLI)

If you have the Android SDK installed and environment variables (`ANDROID_HOME`, `PATH`) configured correctly, you can build and install the project from the root `AdSkipRemote` directory using the Gradle wrapper.

*   **Build APKs for both modules:**
    ```bash
    ./gradlew assembleDebug
    ```
*   **Install the phone app:**
    ```bash
    ./gradlew :app:installDebug
    ```
*   **Install the watch app:**
    ```bash
    ./gradlew :wear:installDebug
    ```

## 3. Development Conventions

*   **Asynchronous Work:** The project uses **Kotlin Coroutines** for handling asynchronous tasks, such as sending messages between devices.
*   **UI State Management:** The watch app uses a simple `Enum` class (`ButtonState`) and `mutableStateOf` to manage the UI state in its Composable functions.
*   **Permissions:** The app declares all necessary permissions in its manifest files, including `VIBRATE`, `WAKE_LOCK`, `BIND_ACCESSIBILITY_SERVICE`, and `BIND_TILE_PROVIDER`.
*   **Testing:**
    *   **Wear OS UI Test:** A UI instrumentation test (`SkipAdScreenTest.kt`) has been added for the `wear` module. This test verifies that the main "SKIP AD" button is present and that its text correctly changes to "Sending..." when clicked.
    *   **Execution:** These tests require an Android emulator or a physical Wear OS device to run. They cannot be executed directly in this environment.
    *   **Further Testing:** More comprehensive tests, such as unit tests for the communication logic or instrumentation tests for the `AccessibilityService` on the phone app, could be added in the future.
